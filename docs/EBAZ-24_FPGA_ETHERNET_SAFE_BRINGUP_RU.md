## Фактическая архитектура и основное ограничение

У нашей EBAZ4205 ARM Cortex-A9, NAND, SDIO и консольный UART `ttyPS0` являются аппаратными блоками PS. Ethernet GEM аппаратно тоже находится в PS, **но MII/MDIO к IP101G PHY проходит через PL (EMIO)**. Поэтому простая полная конфигурация PL только со светодиодами выключит тракт Ethernet и оборвёт SSH.

**PS UART не зависит от PL электрически.** Однако работа Linux с отсутствующим после реконфигурации AXI BRAM/UARTLite может привести к ошибкам или зависанию, так что UART не гарантирует программное восстановление. Перезагрузка с неизменённой NAND ожидаемо возвращает заводской PL; восстановление в данном эксперименте ещё не проверено.

## Способы загрузки

1. **Linux PCAP / `/dev/xdevcfg`**: старый драйвер PetaLinux 2016.4 предоставляет путь для полной перезагрузки PL без внешнего программатора. В документации Xilinx старого поколения есть сценарий передачи файла `.bit` через устройство.
2. **U-Boot FPGA commands**: ещё один способ загрузки логики из RAM до старта Linux; формат и адрес необходимо сверять с конкретным установленным U-Boot.
3. **JTAG через Vivado**: удобный запасной вариант, но физический программатор для начальной PCAP-лаборатории **не обязателен**.

**NAND (в том числе `mtd5`) ни в одном из наших первых экспериментов не перезаписываем.**

## Шлюзы готовности

- **G0 — состояние платы**: убедиться, что PS UART физически подключён, обычное полное отключение/включение питания загружает исходный NAND bitstream и Ethernet. Желательно иметь офлайн-копию NAND `mtd5` (только чтение, с размером и SHA256), доступную для восстановления.
- **G1 — сборка на ПК**: self-checking тестбенч, Vivado synth/opt/place/route, отсутствие критических DRC, осмысленный timing, проверка точной микросхемы `xc7z010clg400-1`, SHA256 и длины `.bit`.
- **G2 — диагностика**: выполнить с PS UART `board/preflight.sh` **только чтение**, проверить `/dev/xdevcfg`, `/proc/mtd`, SD mount, состояние сети.
- **G3 — первый аппаратный опыт**: передать `.bit` на SD и загрузить PL из UART-сессии PCAP; ожидать потерю Ethernet. Не пользоваться SSH как единственным каналом.
- **G4 — откат**: выполнить полное отключение и новое включение питания, убедиться, что заводская NAND снова даёт Ethernet/SSH и что тест кнопок SW2/SW3 продолжает работать. Результат фиксировать как PASS только по реальному выводу.

## Где почитать протокол

[Проект EBAZ-24.1](../rtl/ebaz24-led-blink/README.md). Начальная версия экспериментального PL **не включает Ethernet или прежние AXI IP**. Схему сохранения MII/EMIO в новой полной FPGA-конфигурации следует реализовывать следующим этапом, а не смешивать с первым LED-опытом.

Уточнение: новая конфигурация FPGA с корректным Ethernet может восстановить связь **после** загрузки bitstream, но не гарантирует отсутствие кратковременного обрыва **во время** полной конфигурации. Для непрерывного Ethernet потребовалась бы предварительно предусмотренная архитектура частичной реконфигурации, которой у нас сейчас нет.

**Примечание о праве:** для прямого включения чужих HDL исходников следует проверить лицензию. Полное восстановление закрытого заводского bitstream по опубликованным XDC не гарантировано.
