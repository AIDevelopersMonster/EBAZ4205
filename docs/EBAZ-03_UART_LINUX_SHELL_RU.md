# EBAZ-03 — Как войти в Linux EBAZ4205 через USB–TTL и U-Boot (без майнера)

**Статус:** проверено на конкретной плате EBAZ4205-2G-43; `UBOOT_UART_CONTROL_PASS` → `LINUX_SHELL_NO_MINER_PASS`.  
**Цель:** от подключения UART до приглашения `sh-4.3#`, без записи в заводскую NAND.

> **Внимание:** эта процедура запускает диагностическую оболочку Linux с правами `root` вместо обычного `init`. Это не полноценный штатный режим с запущенными сетью и SSH. Не перепрошивать NAND, не выполнять `saveenv` и не выходить из оболочки PID 1 через `exit`.

## 1. Что потребуется

- Плата EBAZ4205 (проверенная конфигурация — Xilinx Zynq XC7Z010, 256 MiB DDR, 128 MiB NAND).
- USB–TTL UART-адаптер с **логическими уровнями 3,3 В**, например на CH340 / CP2102 / FT232, USB-кабель и три провода.
- Независимый источник питания платы с проверенной для вашей ревизии распиновкой и полярностью.
- ПК с Windows, установленным драйвером адаптера и **PuTTY** (или другим последовательным терминалом).

**Нельзя:** подключать к UART настоящий RS-232 (уровни ± напряжения), подавать 5 В на RX/TX или питать всю EBAZ4205 от вывода VCC USB–TTL. Разъём/контактные площадки UART и порядок выводов следует проверять по конкретной ревизии платы, а не угадывать по расположению на фотографии.

## 2. Подключение UART

**При выключенном питании платы** соедините:

| USB–TTL | EBAZ4205 |
| --- | --- |
| TXD (выход адаптера) | RXD платы |
| RXD (вход адаптера) | TXD платы |
| GND | GND |
| VCC / 3V3 / 5V | **Не подключать** |

USB–TTL вставляем в USB-порт ПК. Питание EBAZ4205 подключаем **отдельно**, только к достоверно определённому входу питания.

## 3. Открытие терминала

1. В «Диспетчере устройств» Windows найдите COM-порт адаптера.
2. В PuTTY выберите **Connection type: Serial**.
3. Укажите соответствующий `COMx` и `Speed: 115200`.
4. В `Connection → Serial` проверьте:

| Параметр | Значение |
| --- | --- |
| Speed (baud) | `115200` |
| Data bits | `8` |
| Stop bits | `1` |
| Parity | `None` |
| Flow control | `None` |

Откройте сеанс и по возможности заранее включите логирование в PuTTY. Сырой лог **не публиковать**, пока из него не удалены идентификаторы, сетевые настройки и пароли.

## 4. Перехват U-Boot клавишей d

1. Питание EBAZ4205 выключено; PuTTY уже открыт.
2. Начните **многократно нажимать маленькую латинскую `d`** в окне PuTTY.
3. Продолжая отправлять `d`, включите питание платы.
4. Дождитесь приглашения загрузчика.

На проверенной плате видно:

```text
U-Boot 2015.07 (Jun 28 2017 - 21:05:18 +0800)
DRAM:  ECC disabled 256 MiB
NAND:  128 MiB
Hit 'd' to stop autoboot(eric): 0
zynq-uboot>
```

**Важно:** число `0` означает, что окно перехвата очень короткое. Начинать нажимать `d` надо **до появления этой строки**. Если сразу пошла загрузка Linux и майнера, выключите питание и повторите. Нажатие Enter в работающем майнере не является заменой перехвату загрузчика.

## 5. Проверить сценарий загрузки (только чтение)

Вводите **по одной строке**, каждый раз дожидаясь `zynq-uboot>`:

```text
version
printenv modeboot
printenv nandboot
printenv nandroot
```

Для **этой** исследованной платы подтверждено:

```text
modeboot=nandboot
nandroot=setenv bootargs 'console=ttyPS0,115200 root=/dev/mtdblock6 rootfstype=jffs2 noinitrd rw rootwait'
```

Заводская переменная `nandboot` читает из NAND конфигурацию FPGA, ядро Linux и Device Tree, затем передаёт управление ядру. **Если значения у вашей платы отличаются, не используйте следующие команды вслепую:** особенно важно расположение корневой файловой системы.

## 6. Временно заменить штатный init на /bin/sh

На приглашении `zynq-uboot>` введите **одной строкой**:

```text
setenv nandroot 'setenv bootargs console=ttyPS0,115200 root=/dev/mtdblock6 rootfstype=jffs2 noinitrd ro rootwait init=/bin/sh'
```

Проверяем, что изменение принято:

```text
printenv nandroot
run nandroot
printenv bootargs
```

Ожидаемые параметры ядра:

```text
bootargs=console=ttyPS0,115200 root=/dev/mtdblock6 rootfstype=jffs2 noinitrd ro rootwait init=/bin/sh
```

Здесь `ro` означает монтирование корня только для чтения, а `init=/bin/sh` — запуск командной оболочки в качестве процесса PID 1 вместо обычных сценариев инициализации. Изменение сделано командой `setenv` **только в оперативном окружении U-Boot**. **Не выполнять `saveenv`.**

## 7. Загрузить Linux без майнинговых служб

Когда проверка `bootargs` пройдена, выполните:

```text
run nandboot
```

Наблюдаем загрузку ядра и файловой системы. В нашем испытании появились строки:

```text
Kernel command line: console=ttyPS0,115200 root=/dev/mtdblock6 rootfstype=jffs2 noinitrd ro rootwait init=/bin/sh
VFS: Mounted root (jffs2 filesystem) readonly on device 31:6.
sh: cannot set terminal process group (-1): Inappropriate ioctl for device
sh: no job control in this shell
sh-4.3#
```

Предупреждения `no job control` и `cannot set terminal process group` ожидаемы для этой диагностической оболочки и **не являются ошибкой загрузки**.

**Контрольная точка: приглашение `sh-4.3#`.** Оно означает доступ к работающему Linux без стандартного запуска майнингового комплекса.

## 8. Подтверждение результата (команды просмотра)

В оболочке `sh-4.3#` выполните:

```sh
uname -a
id
mount -t proc proc /proc
cat /proc/cmdline
cat /proc/mtd
ps
```

В нашем журнале подтверждено:

```text
sh-4.3# id
uid=0(root) gid=0(root)

sh-4.3# uname -a
Linux (none) 4.6.0-xilinx #5 SMP PREEMPT Mon May 8 14:36:49 CST 2017 armv7l GNU/Linux
```

Команда `ps` показывала `PID 1 /bin/sh` и потоки ядра, без майнингового приложения. Каталог `/etc/rcS.d/` существует; скрипт `S95cgminer.sh` штатно настраивает сеть и запускает `/opt/system/appstartup` — в данном диагностическом запуске он не исполняется.

## 9. Что не делать и как вернуться к обычной загрузке

- Не выполнять `saveenv`, `nand erase`, `nand write`, `flash_erase` и не изменять загрузочные разделы.
- Не переводить корневую файловую систему в режим записи до создания резервной копии.
- Не завершать `/bin/sh` командой `exit`: это **PID 1**.
- Не ожидать активных SSH, сетевой конфигурации и веб-интерфейса — штатный `init` не запускался.
- Для возврата к стандартной загрузке **выключите питание платы и включите снова без нажатия `d`**. Поскольку `saveenv` не выполнялся, временные изменения переменных U-Boot не сохраняются.

## 10. Диагностика проблем

| Симптом | Проверка |
| --- | --- |
| Есть текст загрузки, но нажатие `d` не действует | Убедиться, что TX адаптера соединён с RX платы, есть общий GND и выбран правильный COM-порт |
| Не успевает появиться `zynq-uboot>` | Начать нажимать `d` **до** включения платы |
| `Unknown command 'printenv'` или склеенные слова | Вводить короткие команды вручную, по одной; проверить UART и настройки потока |
| Вместо `sh-4.3#` запустился майнер | Проверить `printenv bootargs`: обязателен `init=/bin/sh`; затем повторить процедуру |
| Загрузка останавливается с ошибкой | Сохранить журнал, не писать в NAND; проверить, совпадает ли реальная заводская схема с приведённой |

## 11. Контроль результата

- `EBAZ-00: UBOOT_UART_CONTROL_PASS` — наблюдалось приглашение `zynq-uboot>`.
- `EBAZ-03: LINUX_SHELL_NO_MINER_PASS` — наблюдалось приглашение `sh-4.3#`; `id` сообщил `uid=0(root)`.
- Источник: реальные UART-журналы исследуемой EBAZ4205, 03.11.2026. Логи следует хранить локально с удалением чувствительных данных перед публикацией.

**Дальнейшая работа:** резервное копирование заводской NAND, исследование `/opt/system/appstartup`, затем проектирование штатного режима Linux без майнинговых служб. Это **отдельные работы**, и данная инструкция не выполняет их автоматически.
