# EBAZ-15 — Подготовка восстановленной EBAZ4205 к передаче покупателю

**Статус:** концепция / проект процедуры. **Не реализовано на продаваемой партии.**  
**Дата фиксации:** 2026-11-04.  
**Основа:** [EBAZ-14 — автономный Linux без майнера](EBAZ-14_AUTONOMOUS_LINUX_BOOT_RU.md).

## 1. Назначение и границы

Предполагаемый продукт — **восстановленная бывшая в употреблении плата EBAZ4205**, перепрофилированная под **учебные, экспериментальные и специальные лабораторные задачи** с PetaLinux, ARM и FPGA. Это **не** новый контроллер и **не** сертифицированный модуль для включения в состав коммерческих/ответственных изделий. Покупателю нужно прямо сообщать о б/у происхождении, заводской старой версии ОС и выполненных изменениях.

Подготовка EBAZ-14 ориентирована на **личную лабораторию**: были установлены публичные SSH-ключи конкретных компьютеров. Для передачи покупателю такая конфигурация **не подходит**. Нужен отдельный этап первичного доступа и смены владельца.

## 2. Что уже проверено, а что только планируется

**Проверено на текущей исследуемой плате (EBAZ-14):**

- Штатная загрузка PetaLinux без майнинговых процессов.
- DHCP через `/etc/network/interfaces`.
- Работа Ethernet после позднего восстановления автосогласования PHY в `/etc/rc5.d/S05eth-autoneg`.
- Автоматический Dropbear SSH и подключение по ключу.
- Обычная перезагрузка и холодный старт (холодный старт подтверждён владельцем).
- Резервное копирование данных всех девяти MTD-разделов NAND **без OOB**.

**Ещё не проверено для EBAZ-15:** повторяемая персонализация произвольного экземпляра, первый вход покупателя, безопасное удаление сервисных реквизитов, отдельный тест партии NAND, приёмочная процедура и комплект передаваемых материалов.

## 3. Целевая схема передачи устройства

1. **Сервисная стадия.** Плата приводится к проверенному состоянию EBAZ-14 (майнер не запускается, Linux, DHCP и SSH функционируют).
2. **Персонализация конкретного экземпляра.** Уникальный идентификатор/имя, уникальные ключи SSH-сервера, индивидуальный первоначальный способ входа. Ни один приватный ключ или единый пароль **не должен повторяться между продаваемыми платами**.
3. **Удаление доступа лаборатории.** Удалить публичные ключи сервисных компьютеров из `authorized_keys`, лишние аккаунты, историю команд, временные файлы, сетевые секреты. Только **после** подтверждения клиентского способа входа; обеспечить возможность восстановить доступ через UART в сервисе.
4. **Первый вход покупателя.** Подключение питания и Ethernet к роутеру; поиск IP через таблицу DHCP по MAC; вход по выданным индивидуальным реквизитам или через специально предусмотренную первичную настройку.
5. **Смена реквизитов владельцем.** Задание собственного пароля/публичного SSH-ключа и подтверждение повторного входа. По окончании — запрет парольного SSH, если клиент выбрал ключевую схему.
6. **Приёмка и передача.** Контрольный старт, проверка интерфейса и служб, документ для покупателя, честная фиксация ограничений экземпляра.

### Варианты первичной настройки — решение пока НЕ принято

- **А. Индивидуальный временный пароль** для первого SSH-входа в локальной сети с обязательной сменой и последующим отключением парольного входа. Потребует отдельной безопасной конфигурации Dropbear: текущий EBAZ-14 использует `-s` и пароль не принимает. Не выдавать общий пароль и не оставлять пустой пароль root.
- **Б. Первичная настройка через UART** — безопаснее с точки зрения удалённой авторизации, но потребует USB–TTL у покупателя; хуже для массовой продажи.
- **В. Отдельный мастер первичной настройки** (после разработки и проверки). Пока не утверждать наличие такого мастера.

**Открытая задача EBAZ-15:** выбрать сценарий входа с учётом удобства покупателя, старого Dropbear и отсутствия публичного подключения к Интернету.

## 4. Проверка NAND: только щадящий подход на данном этапе

**Принципиальное решение:** **не требуется** стирать всю NAND, переписывать её тестовыми шаблонами и затем восстанавливать образ **только ради предварительной приёмки**. Разрушающие тесты на каждой б/у плате пока не планируются.

Предполагаемые **неразрушающие** проверки:

- Изучить `dmesg` на ошибки MTD/NAND, ECC и JFFS2, фиксировать количество и адреса сообщений.
- Считать и зафиксировать таблицу MTD, сведения о bad blocks и доступных резервных областях **без изменения BBT**.
- Проверить стабильность чтения важных файлов, наличие ошибок ввода-вывода; при необходимости получить диагностический дамп (чтение `nanddump`, без записи).
- Выполнить несколько запусков Linux, проверить устойчивость SSH и сети после холодного старта; фиксировать результат по конкретной плате.
- При обнаружении `wrong data CRC`, повторяющихся ошибок ECC, новых плохих блоков или нестабильной загрузки — **не объявлять NAND исправной**; отправить экземпляр на углублённую диагностику либо отказаться от его продажи в заявленной конфигурации.

**Ограничение:** успешное чтение и загрузка не доказывают остаточный ресурс NAND. Без полного испытания нельзя гарантировать отсутствие скрытых дефектов. Исходные бэкапы EBAZ-14 были без OOB и не являются автоматически готовым сценарием восстановления.

**Запрещено как рутинная диагностика без отдельного решения:** `flash_erase`, `nandwrite`, разрушающие режимы `nandtest`, массовая перезапись всех разделов.

## 5. Минимальный приёмочный лист отдельной платы

- [ ] Визуальный осмотр, питание, Ethernet/UART и ревизия платы зафиксированы.
- [ ] Подтверждено, что это восстановленная б/у плата, без назначения для встраивания в ответственные изделия.
- [ ] Linux стартует после отключения/повторной подачи питания.
- [ ] Нет процессов `appstartup`, `dwang_btc_miner`, `appweb`, `cgminer`.
- [ ] Ethernet устанавливает линк, DHCP выдаёт адрес, SSH доступен в локальной сети.
- [ ] Генерированы **уникальные** серверные SSH-ключи этой платы; их fingerprint записан в паспорт экземпляра.
- [ ] Создан и проверен **индивидуальный** способ первичного входа покупателя.
- [ ] Сервисные публичные ключи и временные данные удалены; клиентский доступ проверен повторно.
- [ ] Пароль root **не пустой**; клиентская конфигурация не допускает входа с общим или заводским паролем.
- [ ] Журнал NAND/JFFS2 просмотрен; найденные проблемы описаны отдельно, без необоснованной гарантии исправности.
- [ ] Подготовлена краткая инструкция: питание, подключение к LAN, получение IP, SSH, смена реквизитов, восстановление доступа.
- [ ] Нет публикации реальных паролей, приватных ключей, клиентских данных и дампов NAND в открытом репозитории.

## 6. Что передавать покупателю

Плату; краткое описание характеристик и ограничений; номер/идентификатор экземпляра; схему питания и подключения, подтверждённую для конкретной ревизии; пошаговый первый вход; индивидуальные первичные реквизиты **отдельным безопасным каналом**; документацию по SSH/UART; результаты приёмочных испытаний и сведения об обнаруженных дефектах, если есть.

Система: старый PetaLinux 2016.4 / Linux 4.6.0-xilinx. Не открывать SSH-порт в Интернет; использовать в изолированной или доверенной учебно-лабораторной сети.

## 7. Порядок дальнейшей разработки

**EBAZ-14** сохраняется как инженерная проверенная конфигурация. **EBAZ-15** — самостоятельный пакет: схема индивидуальных доступов → эталонная конфигурация без сервисных секретов → скрипт персонализации → неразрушающий приёмочный контроль → инструкция передачи → испытание на отдельной плате. **На текущей работающей плате сейчас ничего менять не требуется.**
