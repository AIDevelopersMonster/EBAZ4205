# LAB-05 — четыре LED и четыре KEY на 660269A_Y13

**Статус: PENDING — ещё нет проверенного на нашем железе RTL, XDC и результата.**

## Цель
Сначала верифицировать электрическую разводку 660269A_Y13 и уровни сигналов, затем создать собственный Vivado-проект для PL: кнопки KEY1–KEY4 управляют LED1–LED4. При необходимости добавить антидребезг.

## Что известно
На наших фотографиях видны KEY1–KEY4, LED1–LED4, маркировка 660269A_Y13, разъёмы к DATA1–3 и GPIO гребёнки. **Физические выводы FPGA и уровни активного сигнала не измерены.** Предположения из чужих XDC нельзя помечать PASS.

## Подготовлен отдельный тестовый RTL-проект (на нашей плате пока не запускался)

Все исходники написаны для данной лаборатории самостоятельно: [key_led_core.v](rtl/key_led_core.v) (логика и двухтактная синхронизация ключей), [lab05_led_key_top.v](rtl/lab05_led_key_top.v) (STARTUPE2/CFGMCLK), [REFERENCE XDC](constraints/660269A_Y13_REFERENCE.xdc), [Tcl-сборка](scripts/build.tcl) и [тестбенч](tests/tb_key_led_core.v).

Принцип: без нажатий четыре LED показывают бегущий огонь; при удержании одной или нескольких кнопок соответствующие LED загораются, остальные гаснут. KEY1…4 — активный **LOW**; LED1…4 — активный **HIGH**. Это **наша новая логика**, не копия поведения Step 2 автора (там четыре KEY влияют лишь на два LED).

**Сначала компьютерная проверка**, без подключения платы (iverilog + vvp):
~~~sh
sh scripts/run_sim.sh
~~~
При успешной симуляции ожидается `LAB05_CORE_SIM_PASS`. **На текущем этапе симуляция в этом коммите не запускалась: iverilog/Vivado в среде подготовки не установлены.** Сборка Vivado 2023.1+ для `xc7z010clg400-1`:
~~~sh
vivado -mode batch -source scripts/build.tcl
~~~
Артефакт будет в `build/lab05_led_key_z010_UNVERIFIED.bit` (игнорируется git). Скрипт **не прошивает** FPGA и не изменяет NAND/SD. Не подавать эту конфигурацию на нашу плату до прозвонки, проверки 3.3 V банков, рабочего UART/JTAG и плана восстановления factory PL/Ethernet.

[Проверенная документация Step 0–7 первоисточника](../../docs/ZX_BULBULATOR_REFERENCE_RU.md), [исходная таблица REFERENCE в CSV](../../hardware/adapters/660269A_Y13/ZX_BULBULATOR_REFERENCE_PINMAP.csv).

## План работ
1. [Зафиксировать ревизию и проверить разъёмы](../../hardware/adapters/660269A_Y13/README.md): непрерывность сигнала, земля, питание, соответствие подписей корпусу Zynq.
2. Составить проверенную таблицу connector → Zynq package pin → LED/KEY, с независимой проверкой напряжения банка и IOSTANDARD.
3. Создать собственные RTL, simulation testbench, XDC и воспроизводимую процедуру сборки в rtl/ или рядом с уроком.
4. **До временной конфигурации PL** подготовить UART/JTAG recovery: factory PL на нашем экземпляре обслуживает Ethernet. Никаких команд записи NAND, mtd5 или U-Boot env.
5. Провести испытание на оборудовании и приложить журнал/видео. Только затем поднять статус до PASS.

Полезные внешние примеры: [tomorrow56](https://github.com/tomorrow56/EBAZ4205_tutorial) и [ZX_BulbuLator](https://github.com/Alex-Electron/ZX_BulbuLator). Ссылки для изучения; исходники автоматически не копируются.

**Не путать:** PASS кнопок SW2/SW3 PS в LAB-02 не является PASS кнопок KEY1–KEY4 PL на переходнике.
